SFEX Animation Format:

header:
first word: first meta data entry directly after header end
remaining words are offsets to others meta data entries
00 00 00 08 or 01 00 00 08 ->  delemiter value between meta data

meta data:
first word: entries length
second word: if zeroed it does cancel the frame duration value
a value of 0x02 enable the frame duration
the values 0x06, 0x0A, 0x0E make the character move weirdly and enable the frame duration
any other value make the character jump or cancel the frame duration value
starting from word 3, there is a series of two words entries: frame duration / frame data offset
equal to the entries length value
actually the frame duration is divided in two half (two short) the first is the duration,
the second is which hands meshes to use
at the end of each meta data entry there is a delemiter value: 00 00 00 08 or 01 00 00 08
preceded by two words: an unknown word value, probably last frame data offset, and a zero word
also 01 00 00 08 means: loop animation and  00 00 00 08 means: do not loop

frame data:

first three short int (two bytes each) of the first frame data is the root axis shift position
then come two short int for root axis rotation and the rest of data are bones rotations angles
the root axis shift position is three short only for the first frame, for the rest it is three bytes only
the first frame's root axis shift position is how much the character's cenrer (root) shift from the ground-up
the rest of the frames's root axis shift position are accumulative delta values, they simulates
inverse kinematic to grounds the character, if they are not applied the character's animations will
be ungrounded and he will looks like floating, also the delta values are in z y x format and must be negated before used

all bones have 1 word (4 bytes) for rotation, except shoulders which have 2 words, so
they translates 2 times and rotates 2 times around 3 axis

all meshes must be rotated 90 degrees around Y axis, and 180 degrees around Z axis
before applying any rotation.
also the bones rotations angles and initial positions must be negated before used


the rotations are in this order:

number of short int:   mesh:
2                      root axis rotation
2                      lower torso
2                      upper torso
2                      head
4                      right shoulder
2                      right elbow
2                      right hand
4                      left shoulder
2                      left elbow 
2                      left hand
2                      waist
2                      right hip
2                      right knee
2                      right feet
2                      left hip
2                      left knee
2                      left feet


rotation format:
Angle 1 (Roll): Bits 7-5 of Byte 0 + Byte 1


Angle 2 (Yaw): Bits 4-2 of Byte 0 + Byte 2


Angle 3 (Pitch): Bits 1-0 of Byte 0 + Byte 3

    // Angle 1 (Roll): Top 3 bits of Byte 0 are high bits, Byte 1 is low bits
    // Logic: ( (Byte0 >> 5) << 8 + Byte1 ) * 2
    int angle1 = (((b0 >> 5) << 8) | b1) * 2;

    // Angle 2 (Yaw): Middle 3 bits of Byte 0 are high bits, Byte 2 is low bits
    // Logic: ( ((Byte0 << 6) & 0x700) >> 8 is the high bit, but easier to mask Byte 0: )
    int angle2 = ((((b0 & 0x1C) >> 2) << 8) | b2) * 2;

    // Angle 3 (Pitch): Bottom 2 bits of Byte 0 are high bits, Byte 3 is low bits
    // Logic: ( (Byte0 & 0x03) << 8 + Byte3 ) * 4
    int angle3 = (((b0 & 0x03) << 8) | b3) * 4;

    // to convert to degrees, multiply by (360.0 / 4096.0)

in ZYX format

bones initial positions and hierarchy:
at vram address 0x801B4C68 (at position 0xB4468 in the executable file) in the european version, there is an array of structs defining the bones initial positions and hierarchy, it is defined as follow:

typedef struct
{
    Vector3D* intial_position;
    BoneMap*  children_info;
    int       joints_count;
}BoneInfo;

where Vector3D and BoneMap are defined as follow:

typedef struct
{
    int16_t x, y, z;
}Vector3D;

typedef struct
{
    uint8_t children_count;
    uint8_t children_indexes[7];
}BoneMap;


Vector3D* intial_position is pointer to an array of bones meshes initial position / axis shift
BoneMap* children_info is a pointer to an array bones joints children indexes

the numbers of Vector3D intial_position, and BoneMap children_info for each character is equal
to joints_count variable

the initial positions / translations must be scaled like so before they are used:

    int16_t x = (int16_t) ((int32_t) (init_pos->x * 0xF) >> 7);
    int16_t y = (int16_t) ((int32_t) (init_pos->y * 0xF) >> 7);
    int16_t z = (int16_t) ((int32_t) (init_pos->z * 0xF) >> 7);


the the initial positions / translations are in this order:

number of short int:   mesh:
3                      root
3                      lower torso
3                      upper torso
3                      head
6                      right shoulder
2                      right elbow
2                      right hand
6                      left shoulder
3                      left elbow 
3                      left hand
3                      waist
3                      right hip

3                      left hip
