SFEX Model Format:

header:
the header start with a 32 bit (4 bytes) value indicating the number of meshes.
after that there is a sequence of 32 bit value indicating the offset of each mesh data in the file (in 32 bit word (value * 4)), 
the sequence length is equal to the number of meshes, and each mesh data end with a 0xffffffff value.

data:
between meshes data there is a 0xffffffff delimiter value.
the first mesh data start immediately after the header end.
first two bytes: indicate the number of entries to read
next two bytes: indicate the size/type of each entry, usually 0x24, 0x0c, 0x34 for triangles and 0x2c, 0x3c for quads.
also 0x24 and 0x2c indicate flat shaded polygon, whereas 0x0c, 0x3c, 0x34 indicate gouraud shaded.
next word (32 bit): delimiter value at the start of the each entry, usually 0x78000028, it repeat at the start of each entry in the mesh primitive data.
it also indicate the CLUT number to use with the texture, example: 0x78000028 for CLUT 1, 0x78040028 for CLUT 5.
then after that start the primitive data.
primitive data comes in triangles or quads packets, each entry contains vertices, texcoords and normals.
the first two words are textcoords, each two bytes are u and v coordinates, 
next 6 or 8 words (depending on if it is a triangle or a quad) are vertices positions, 
each vertex take up 2 words, so two bytes for each x, y, z coordinates, and last two bytes are always zero.
last two words are normals, two bytes for each x, y, z coordinates, and last two bytes are always zero.
some normals take up more than two words if the size/type bytes are 0x0c or 0x3c or 0x34.
when the end of entries is reached, if the next word is 0xffffffff then it indicate the end of the mesh data, 
if the value is not 0xffffffff, then again first two byte indicate the number of entries to reads, and
the next two bytes indicate the size/type of each entry.



extra dynamic meshes:
some extra meshes that moves and morphs dynamically with the characters as
they moves, to simulate clothes, hair and others accessories, like ryu's black-belt and headband 
and sakura's skirt and headband are auto generated by the game's code on the fly, the functions 
that are responsible of that resides in the character's overlay file, at the start of each
character overlay file there is an array of functions pointers, and pointer (11, 12) at offsets (0x28, 0x2C)
seems to always be used to store meshes generation functions addresses, otherwise they are zeros

Overlays load address:

player overlays (PLXX_1.OVL) at: 0x80043000

opponent overlays (PLXX_2.OVL) at: 0x8008CA00
